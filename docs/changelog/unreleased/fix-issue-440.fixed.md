- [§FS-fmt.2.3.5](../../functional-spec/FS-fmt.md#235-an-inline-code-span-closes-on-a-run-of-its-own-length), [§REQ-no-missed-citation.2](../../requirements/REQ-no-missed-citation.md#2-every-blind-spot-is-declared-and-bounded), [§REQ-backwards-compatibility.5](../../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), [§DF-inline-code-span-closes-on-its-own-run](../../decisions/functional/DF-inline-code-span-closes-on-its-own-run.md#df-inline-code-span-closes-on-its-own-run-an-inline-code-span-closes-on-a-run-of-its-own-length): a Markdown inline code span now closes at the next run of backticks as long as the one that opened it, as CommonMark reads it, so a citation after a double-backtick span that holds a single backtick is prose again. `grund fmt` paired backticks one at a time, so it read the rest of such a line as code: `fmt --write` left a stale cross-reference anchor there and reported the file clean, and the broken link reached a commit; inside such a span it read the text before the inner backtick as prose and rewrote a citation in code. One predicate answers for every pass of `fmt`, the LSP on-type transform and every inline-code reading of `grund check`, so they move together. An opener that does not close on its line still leaves the rest of the line code, because a span may continue onto the next line. The verdict moves both ways, and four ways a passing tree can now fail are named in the decision: `fmt --check` asks for the rewrite a citation after the span was always owed; `check` raises the canonical-form error for a number-only shorthand after the span; a wrapped index entry inside a span stops being an entry; and in a workspace source file a marked qualified citation inside a span is skipped, so its declaration may go uncited. Every finding that replaces the old verdict names its location and the action to take: run `grund fmt --write`, or move the entry or the citation out of the span.
