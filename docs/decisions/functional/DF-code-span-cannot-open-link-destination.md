# DF-code-span-cannot-open-link-destination: code punctuation cannot open a destination in later prose

**Date:** 2026-11-23

## status: Accepted

## 1. Decision

The destination opener scan passes inline-code spans over whole before looking for an unescaped `](`, as [§FS-citations.zones.link-destination](../../functional-spec/FS-citations.md#zoneslink-destination-a-link-destination-is-the-url) now makes explicit by citing [§FS-citations.zones.inline-code](../../functional-spec/FS-citations.md#zonesinline-code-an-inline-code-span-closes-on-a-run-of-its-own-length). Reuse that span reading rather than defining another. Once an actual destination opens, its existing parenthesis balancing and unclosed-line protection remain authoritative, including when its bytes contain backticks.

Issue #1487 exposes a second reading: the shared destination predicate searches raw bytes through a closed code span, mistakes its `](` for an opener, and protects later prose through the end of the line. This is a correction of that shared predicate, not a new Markdown grammar or a special case in the cross-reference pass.

## 2. Consequences

The formatter, scanner rewrite exemptions, bare-token recognition, index entry classification and enrollment, hover linkification and on-type edits share this boundary. Only sites whose destination classification came from punctuation inside inline code change; actual destinations retain their extent and formatting preserves code bytes.

- `fmt --cross-refs --check` can change from clean to exit 1: it now proposes both whole-declaration and section links in later prose, and re-derives stale wraps there. The trigger, marker and shorthand passes can likewise propose previously suppressed edits. `grund fmt --marker --cross-refs --write` applies those formatting repairs.
- `check` can now report a canonical-form error for a shorthand after the span. In a v1 project with `strict = false`, a bare citation after the punctuation, inside the span or in later prose, is recognized rather than silently lost; inline code was never an exclusion for bare citations; a dangling one, missing section, forbidden direction or non-canonical form is judged as in any other prose. Citations in the code span itself retain their existing recognition policy.
- A bare index citation after the span now receives `unlinked-index-entry`, whose formatter repair is possible, in place of `missing-index-entry`. The default check still fails until repaired, but narrowed `--only` verdicts can flip. Closed wraps were already credited by entry-form classification; that credit is unchanged. An external source declaration can now enroll through its canonical wrap, and that site becomes navigation rather than an ordinary use. Its unused warning can therefore appear, and grounding or citation rules that the index-only use satisfied can fail; write a real use outside the index. Enrollment establishes and satisfies membership in its own index and creates no obligation in other indexes. Counts and citation-rule outcomes also reflect any previously missed bare citation, in either direction.
- Editor hover links and on-type edits now agree with the formatter after the span. No source-string grammar, reference-definition grammar, or multiline code-span behavior changes.

## 3. Proof for the correcting verdict

This record supplies the accepted proof required by [§REQ-backwards-compatibility.5](../../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), rather than treating a released false-clean verdict as an unspecified development surface.

1. **Prior prohibition.** The old verdict violated [§REQ-no-missed-citation.2](../../requirements/REQ-no-missed-citation.md#2-every-blind-spot-is-declared-and-bounded), which forbids a blind spot no specification point names. This prohibition already applied when that verdict shipped in released 0.23.0: tag `v0.23.0`, commit `3cf3846711312f5d80a5209400125bc1559fe8e8`, contains that numbered section at `docs/requirements/REQ-no-missed-citation.md:9`. That tag also contains the destination rule at `docs/functional-spec/FS-citations.md:222` and the span rule at line 248: code closes at its matching run, and text after it is prose for every caller. Neither defines a destination opened by punctuation inside code. The old predicate creates an undeclared blind spot there: the ported issue fixture gets no formatting proposal for either following citation, and the v1 bare-dangling regression returns `success` instead of the required located finding. This proves the conflict using an existing prohibition; this change adds none.
2. **Why neither other route fits.** The [§REQ-backwards-compatibility.2](../../requirements/REQ-backwards-compatibility.md#2-the-deprecation-path) deprecation path does not fit: it would preserve the undeclared blind spot for another release. No authored spelling is being removed: the same code and prose remain legal. The [§REQ-backwards-compatibility.3](../../requirements/REQ-backwards-compatibility.md#3-loud-mechanical-migrations) mechanical route does not cover the correction as a whole. Formatting proposals have a command, but an unresolved bare citation and an index-only use that no longer satisfies a grounding or citation rule require the maintainer to choose the intended target or write a real use. No one shipped command can make those semantic decisions, and the old source bytes carry no format-version mismatch to migrate.
3. **Named release.** The `release-note` below names the correction and its affected verdicts for inclusion in the correcting release under [§FS-distribution.4.6.4](../../functional-spec/FS-distribution.md#464-compatibility-notices-come-from-the-decisions).
4. **Actionable findings.** Formatter proposals name file, line, old text and replacement; run the formatter write command above. `unlinked-index-entry` names its index line and the formatter repair. A newly read citation receives the ordinary located finding: fix its ID, section or direction, expand its shorthand, or mark an intended illustration with the configured escape. An unused finding names the declaration and asks for a real use outside its index; grounding and citation-rule findings likewise name the site and the required use. Newly satisfied edges can remove findings; their removal requires no repair. These are existing findings and remedies, not a new silent verdict.
5. **Bounded licence.** Only the code-span/destination interaction is corrected. Actual closed and unclosed destinations retain their extent and bytes, escaped openers retain their meaning, and the existing span delimiter and escape rules remain the only reading. This correction cannot justify ordinary tightening or unrelated parser change.
