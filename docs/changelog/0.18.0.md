### Compatibility notices

- [§DF-a-buffer-is-the-file](../decisions/functional/DF-a-buffer-is-the-file.md#df-a-buffer-is-the-file-an-editor-buffer-is-the-file-it-names-under-every-spelling-and-with-no-file-saved-behind-it), [§FS-scan.text.buffer-only](../functional-spec/FS-scan.md#textbuffer-only-a-buffer-with-no-file-behind-it-is-a-file), [§FS-scan.identity.buffers](../functional-spec/FS-scan.md#identitybuffers-a-buffer-is-the-file-at-its-physical-location), [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), [§REQ-no-wrong-citation.2](../requirements/REQ-no-wrong-citation.md#2-no-false-alarms): **the editor judges an unsaved file as the saved file, before the save.** A file that exists only as an editor buffer exists, so a stub to it is no longer `stub link target missing` and its ID no longer a `duplicate declaration`. A buffer is the file under every spelling, so an unsaved edit to a stub's target behind a symlink moves the stub at once. A buffer-only file in a directory the walk skips is not read, as the saved file would not be. **Who this breaks:** only editor users, and only before a save. The verdict moves both ways: a stub whose symlinked target loses its declaration in a buffer is `broken-stub` at once, and a citation that resolved only through an unsaved file in an ignored directory dangles. Every finding that replaces the old verdict is one the saved file already gets, naming its location and the fix. The command line, CI and the bindings see no change. Closes [issue #595](https://github.com/agent-grounds/grund/issues/595).
- [§DF-a-title-citation-is-a-citation](../decisions/functional/DF-a-title-citation-is-a-citation.md#df-a-title-citation-is-a-citation-a-citation-on-a-declarations-heading-is-a-citation-unless-it-cites-the-id-that-heading-declares), [§FS-citations.recognized.title-lines](../functional-spec/FS-citations.md#recognizedtitle-lines-a-declarations-heading-cites-what-it-names), [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), [§REQ-no-missed-citation.2](../requirements/REQ-no-missed-citation.md#2-every-blind-spot-is-declared-and-bounded): **a citation in a declaration's title is now a citation.** A title such as `# FS-a: Alpha, built on` a cited `FS-b` now cites it: `refs FS-b` lists it, and `FS-b` is no longer reported unused. Only a citation of the ID the heading declares is still dropped. **Who this breaks:** a repository whose titles cite other IDs. The verdict moves both ways: a title citation that dangles, names a missing section or an unknown project alias, or is a number-only shorthand is now an error (`dangling`, `missing-section`, `unknown-project`, `shorthand-citation`), a direction rule now judges it (`forbidden-citation`, `discouraged-citation`), a glob in a title is a `glob-citation` warning, and every finding names its location and the fix, as for a citation anywhere else. `fmt` still never rewrites a title, so a shorthand there is written out by hand, to the full ID its message names.
- [§DF-bare-block-comment-line-declares](../decisions/functional/DF-bare-block-comment-line-declares.md#df-bare-block-comment-line-declares-a-line-inside-a-block-comment-declares-with-or-without-its-gutter-behind-any-of-its-openers), [§FS-declarations.line.block-comment](../functional-spec/FS-declarations.md#lineblock-comment-a-line-inside-a-block-comment),
  [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), [§REQ-no-wrong-citation.2](../requirements/REQ-no-wrong-citation.md#2-no-false-alarms): **a declaration in a block
  comment is found with or without the ` * ` gutter, and behind a `/**` or `/*!`
  opener.** A bare `FS-b: Beta` line inside `/** … */`, `/** FS-b: Beta` on the opener
  line and the one-line `/** FS-b: Beta */` now declare `FS-b`, so the false
  `unknown reference` on every citation of them goes, and `show`, `list`, `refs`, `cover`
  and the editor find them. A bare line declares only in a block whose `*/` is found.
  `/** ## 1. Sub` on an opener line is now a section heading, as `/* ## 1. Sub` is.
  The verdict moves both ways. **Who this breaks:** a repository with a line inside a block comment that starts, without
  ` * `, with an ID-shaped token of a configured kind. A declaration found there is judged
  like any other: a duplicate of an ID declared elsewhere, a home, index, chapter or
  direction finding, or an unused-declaration warning, and every finding names its
  location and the fix. A bare block line that a configured kind's grammar rejects, followed by a colon, is
  a `declaration-near-miss` error, as its starred twin is. Measured before release over
  grund, rhei, ephor and fissile and their workspace, none of them sees a new finding.
- [§DF-closing-hashes-are-not-the-heading](../decisions/functional/DF-closing-hashes-are-not-the-heading.md#df-closing-hashes-are-not-the-heading-a-headings-closing-hashes-are-not-part-of-its-anchor), [§FS-declarations.heading.rendered-text](../functional-spec/FS-declarations.md#headingrendered-text-a-headings-rendered-text), [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), [§REQ-no-wrong-citation.3](../requirements/REQ-no-wrong-citation.md#3-no-wrong-write): **a heading's closing hashes are not part of its anchor.** `## 1. Steps ##` renders as "1. Steps", whose anchor is `1-steps`, but `grund fmt --cross-refs` wrote `#1-steps-`, a fragment no heading carries, and `show`'s JSON `anchor` said the same. Both now give `1-steps`. **Who this breaks:** a repository holding a cross-reference link to a heading with closing hashes. Its verdict moves once: `fmt --check` reports each such link, and every finding names its file and location and the fix, `grund fmt --cross-refs --write`. Headings without closing hashes keep their anchors, and the `--toc` title keeps its bytes until 0.19.0.
- [§FS-config-v2.schema.sources.declarations](../functional-spec/FS-config-v2.md#schemasourcesdeclarations-declarations-picks-which-comments-declare), [§FS-config-v2.schema.sources](../functional-spec/FS-config-v2.md#schemasources-schemasources): **a v2 project declares source IDs only in doc comments by default.** A `// FS-x: note` inside a function no longer declares `FS-x` in a `grund_config_version = 2` project, so it is no longer reported as a duplicate. Its marked citations still resolve. Write `declarations = "any-comment"` under `[schema.sources]` to keep v1's recognition. Version-1 configurations are unchanged.
- [§FS-scan.scope.extensions.default](../functional-spec/FS-scan.md#scopeextensionsdefault-the-extensions-default-follows-the-language-table), [§FS-inline-citation-style.1.1.2](../functional-spec/FS-inline-citation-style.md#112-languages), [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), [§REQ-no-missed-citation.3](../requirements/REQ-no-missed-citation.md#3-proven-per-host-language): **with no `[scan] extensions`, grund now reads every language it classifies.** The default gains `h cc cxx hpp hh hxx m mm kts jsx mjs cjs dart r R sh bash zsh` after the 26 it already named, and from now on it is `md` plus every extension grund's language table names. Declarations in those files appear in `list`, `refs` and `show`, and their citations are checked. **Who this breaks:** a project with **no** `extensions` key that keeps a stale or misspelled `§` citation in a comment in one of those files under a scanned root. Its `check` moves from `success` to `unknown reference` at that file and line, and newly read declarations can surface `duplicate declaration` errors. **The fix:** correct the citation at the reported line. **To keep the old scan:** write the old 26-entry list as your `extensions`. A project with an explicit `extensions`, which every `grund init` scaffold has, sees no change. The verdict changes by the correction route of [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), because the old default broke [§REQ-no-missed-citation.3](../requirements/REQ-no-missed-citation.md#3-proven-per-host-language), and every finding that replaces it names its location and the fix. Why the default widens rather than warns is [§DF-default-extensions-follow-language-table](../decisions/functional/DF-default-extensions-follow-language-table.md#df-default-extensions-follow-language-table-the-scan-extensions-default-reads-every-language-grund-classifies). Closes [issue #705](https://github.com/agent-grounds/grund/issues/705).
- [§FS-rules.6](../functional-spec/FS-rules.md#6-semantic-deduplication), [§FS-rules.8](../functional-spec/FS-rules.md#8-command-surfaces), [§DF-direction-absorbs-findings-not-rules](../decisions/functional/DF-direction-absorbs-findings-not-rules.md#df-direction-absorbs-findings-not-rules-a-citations-direction-absorbs-a-duplicate-rules-finding-for-a-unit-it-reports-not-the-rule), [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), [§REQ-no-missed-citation.1](../requirements/REQ-no-missed-citation.md#1-no-silent-skips): **a `[citations]` direction no longer hides a duplicate rule's finding it does not report itself.** A rule such as `Each FS must cite at least one REQ.` beside `[citations.FS] must = ["REQ"]` now reports `missing-citation` (or, at `should`, `suggested-citation`) at a declaration whose only `REQ` citation does not resolve — a dangling ID, a missing section, or a dangling citation into a workspace member — which the direction counts and the rule does not. **Who this breaks:** the verdict moves from exit `0` to exit `1` for `grund check --rule … --only-rule` over such a declaration, which printed `success` and now prints `docs/fs/FS-a.md:1: error: FS-a must cite REQ (--rule)`, and for a run that ignores `unknown-reference` or `missing-section`; an unscoped default run gains that line beside the `unknown reference` it already fails on. Every finding that replaces the old verdict names the declaration's location and the kind it must cite, and the fix is to cite a declaration that exists. A unit the direction itself reports is unchanged: its finding wins byte-for-byte. Closes [issue #727](https://github.com/agent-grounds/grund/issues/727).
- [§DF-doc-comment-fenced-heading](../decisions/functional/DF-doc-comment-fenced-heading.md#df-doc-comment-fenced-heading-a-heading-inside-a-fence-in-a-comment-block-is-not-a-section), [§FS-languages.fence.comment-block](../functional-spec/FS-languages.md#fencecomment-block-a-fence-inside-a-comment-block-hides-its-headings),
