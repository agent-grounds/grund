# DA-engine-renders-nothing: the engine renders nothing, so the deprecated compat frontend retires

**Status:** Accepted
**Date:** 2026-09-18

## 1. Context

`grund-core` still contains a frontend. `crates/grund-core/src/compat/` is sixteen files and about 3,960 lines: the deprecated `grund_core::main_entry()` process entry point, one `command_*` adapter per subcommand — each parsing argv, printing text or JSON, and returning an exit code — and the report printers behind them. The published `grund` CLI has its own renderer for the same output, and `tests/integration/check_frontend_parity.rs` and `tests/integration/refs_frontend_parity.rs` exist to hold the two byte-identical.

Two architecture points say this should not exist. [§AR-bindings.2](../../architecture/AR-bindings.md#2-grund-core-the-only-place-logic-lives) puts every check, every regex and every walk in the engine and leaves parsing, rendering and exit-code policy to a frontend; [§AR-system.4](../../architecture/README.md#4-dependency-direction) states the consequence as a test — the engine writes no stream and exits no process — and [§AR-system.2.9](../../architecture/README.md#29-api) records `compat/` as the standing exception, "the one directory that may write to a stream and a set that may shrink and never grow". Two renderers for one output is a cost paid by every change to a message, and the parity tests are the shape of that cost: they exist only because there are two.

The set has shrunk as far as it can on its own. Every data half these adapters once mixed with their printing has already left — the queries into `queries/`, the writers into `writers/`, the check run and the scope cautions into `api/` — so what is left is argv, bytes and exit codes, plus three crossings that no further extraction removes:

1. **Four warnings are printed from `compat/` on the live path.** `warn_if_members_absorb_scan`, `warn_unread_block`, `warn_undecidable_ancestor_claim` and `print_unlisted_workspace_block_warnings` are called from `workspace/` — the component seven levels below the frontends — on *every* walking command: [§FS-check.4.7](../../functional-spec/FS-check.md#47-a-workspace-member-swallows-the-blocks-own-scan) (members absorbed the scan), [§FS-check.4.8](../../functional-spec/FS-check.md#48-unlisted-workspace-block) (an unlisted `[workspace]` block), [§FS-check.4.10](../../functional-spec/FS-check.md#410-include_root--false-leaves-the-blocks-own-files-unread) (an opted-out block's unread files) and [§FS-workspace.6.1](../../functional-spec/FS-workspace.md#61-nested-workspaces) (an undecidable ancestor claim). They are settled during workspace expansion, before any report exists, and `check`, `list`, `refs`, `cover`, `fmt` and the LSP snapshot all resolve that boundary. These four are the one direction [§AR-system.4](../../architecture/README.md#4-dependency-direction) forbids outright that the module split could not remove.
2. **`run_integrations` is public and `grund-cli` imports it from the engine.** It is the one `command_*` symbol the published CLI still calls, so `lib.rs` re-exports a renderer and [§AR-bindings.2](../../architecture/AR-bindings.md#2-grund-core-the-only-place-logic-lives)'s own claim — that the CLI "imports no `grund_core::command_*` symbol" — holds only because this one is spelled differently.
3. **`main_entry()` has been deprecated since 0.4.1 without naming the release it stops working in.** [§REQ-backwards-compatibility.2](../../requirements/REQ-backwards-compatibility.md#2-the-deprecation-path) requires release `N` to ship the warning naming that release, with the old form dying no earlier than `N+1`. Nine minor releases have shipped the warning without the name, so the deprecation has no end and the directory it anchors cannot be removed.

## 2. Decision

`compat/` retires. Each of the three crossings is answered rather than carried, and the removal takes two releases.

**The four warnings travel as diagnostics in the run's warning channel.** The engine returns them; each frontend renders them. This is the channel the engine already has: the scope cautions in `api/scope_cautions.rs` — the empty scan of [§FS-check.2.2](../../functional-spec/FS-check.md#22-empty-scan), the nothing-recognized caution of [§FS-check.4.5](../../functional-spec/FS-check.md#45-nothing-recognized), the redundant `--full` of [§FS-check.1.3](../../functional-spec/FS-check.md#13-the-full-tree-scope---full) — are `Diagnostic`s that print nowhere, built by one function that the CLI and the LSP snapshot both read ([§FS-check.2.2](../../functional-spec/FS-check.md#22-empty-scan), [§FS-check.4.5](../../functional-spec/FS-check.md#45-nothing-recognized)). The four join them, on every command that walks rather than on `check` alone, since the finding is already specified as one every walking command carries.

**Each anchors at the `grund.toml` line its message already names**, carried as the finding's own location rather than only as text inside the message: the `members` line for [§FS-check.4.7](../../functional-spec/FS-check.md#47-a-workspace-member-swallows-the-blocks-own-scan), the `[workspace]` line for [§FS-check.4.8](../../functional-spec/FS-check.md#48-unlisted-workspace-block), the `include_root` line (falling back to `[workspace]`) for [§FS-check.4.10](../../functional-spec/FS-check.md#410-include_root--false-leaves-the-blocks-own-files-unread), and — for [§FS-workspace.6.1](../../functional-spec/FS-workspace.md#61-nested-workspaces) — the config file with no line, because the `members` value whose line would be the anchor is exactly what could not be read.

**No byte a user reads moves.** Each keeps the shape its own spec section fixes: the CLI-level `warning:` line on stderr ([§FS-check.2.1.1](../../functional-spec/FS-check.md#211-cli-level-messages)), the same text under `--format json` for the three launch-time ones, and [§FS-check.4.8](../../functional-spec/FS-check.md#48-unlisted-workspace-block)'s one JSON warning object with `path`, `line` and `sites` still `null`. The render shape is a property of the finding, not a consequence of whether a location is known, and none of the three gains a JSON `code` — so the selector vocabulary of [§FS-check.1](../../functional-spec/FS-check.md#1-inputs) does not grow either.

**The LSP gains a reader it never had.** It publishes the four on the `grund.toml` each one anchors at ([§FS-lsp.1.1](../../functional-spec/FS-lsp.md#11-diagnostics)), and the parity sweep holds them against the same case's stderr golden ([§FS-lsp.4](../../functional-spec/FS-lsp.md#4-determinism-and-parity-with-the-cli)).

**`integrations` moves its argv and its printing into `grund-cli`** ([§AR-bindings.3](../../architecture/AR-bindings.md#3-grund-cli-the-cli-binary)), like every other subcommand's. The engine keeps client detection, artifact rendering and the managed writes as the data-returning functions they already are under `writers/`, and `grund_core::run_integrations` stops being public. Nothing a user sees changes ([§FS-integrations.1](../../functional-spec/FS-integrations.md#1-user-facing-command)).

**`main_entry()` names its releases.** The workspace version is `0.13.2-dev`, so **0.14.0** is the next minor release: it carries the deprecation note and the changelog entry naming **0.15.0** as the release the symbol is removed in, in the `is removed in <release>` clause [§FS-distribution.4.2](../../functional-spec/FS-distribution.md#42-a-release-may-not-contradict-the-releases-the-trees-own-messages-name) now closes. **0.15.0** removes it, and with it `compat/`, every `command_*` adapter, both frontend-parity tests, the `compat_frontend` test binary, and the `#[doc(hidden)]` names that existed only for them ([§FS-distribution.3.1](../../functional-spec/FS-distribution.md#31-rust-grund-core-crate)).

## 3. Why this shape

### 3.1 The engine already has the channel, and it is already the way these four should have travelled

The deciding fact is that nothing new is invented. A run-level caution with no site in the citation graph is a solved problem in this engine: `api/scope_cautions.rs` builds three of them as `Diagnostic`s, and because one function builds them, an editor and a terminal over one tree say the same thing. That file records what it cost to learn — "spelled once per surface it was already wrong once — the LSP kept the empty scan and never grew the second caution, so an editor and a terminal disagreed about one tree". The four `[workspace]` warnings are the same kind of fact and are one `eprintln!` away from the same channel; the text each prints is *already* built in `workspace/` by a data-returning function beside the printer. The change is to return what is built rather than print it.

### 3.2 The anchor is what the editor was missing, and it must not be a parse

An LSP diagnostic needs a file and a range. Every one of these four messages names one — a `grund.toml` and, in three of the four, a line — but it names it *inside the message text*, in the breadcrumb shape [§FS-config.4.3](../../functional-spec/FS-config.md#43-invalid-config-behavior) uses. A frontend that recovered the anchor by parsing that text would be re-deriving in the frontend something the engine knows, which is the one thing [§AR-bindings.2](../../architecture/AR-bindings.md#2-grund-core-the-only-place-logic-lives) forbids a frontend to do. So the anchor travels as the finding's own location. That it is not printed as [§FS-check.2.1](../../functional-spec/FS-check.md#21-report-format)'s `<path>:<line>:` prefix is a separate question, already answered by these sections: a fact about the run's configuration is not a finding at a site in the citation graph, so it keeps the CLI-level shape.

### 3.3 Keeping every byte is what makes this a refactor rather than a change

These four warnings are user-visible text under [§REQ-backwards-compatibility.1](../../requirements/REQ-backwards-compatibility.md#1-what-is-covered), and their exact phrasing is what a repository greps ([§FS-errors.3](../../functional-spec/FS-errors.md#3-message-text)). A change whose entire purpose is to move rendering out of the engine has no business also moving a byte, so it moves none: same streams, same text, same JSON shapes, same exit codes, same `success` suppression. That is what keeps this decision out of [§REQ-backwards-compatibility.2](../../requirements/REQ-backwards-compatibility.md#2-the-deprecation-path) altogether — there is no old form and no new form, only one form rendered from one place. It is also what makes the change testable: the e2e goldens that pin these lines are the proof, unedited.

### 3.4 Two releases, because a deprecation that names no release is not one

`main_entry()` cannot simply be deleted. [§REQ-backwards-compatibility.2](../../requirements/REQ-backwards-compatibility.md#2-the-deprecation-path)'s path is release `N` ships the warning naming the removal release, and the old form dies no earlier than `N+1`; the warning has shipped since 0.4.1 but has never carried the name, so the clock has not started. 0.14.0 starts it and 0.15.0 stops it. The clause matters as much as the numbers: [§FS-distribution.4.2](../../functional-spec/FS-distribution.md#42-a-release-may-not-contradict-the-releases-the-trees-own-messages-name) closes the vocabulary a release gate can read, "so a ramp written in it is seen and a ramp written outside it names no release this gate can read", and that vocabulary had a landed removal clause (`was removed in`) and no pending one. Adding `is removed in <release>` gives a removal the same two tenses a verdict flip already has, and makes this deprecation the first one a machine refuses to publish at the wrong version.

### 3.5 What the removal is worth

About 3,960 lines of the engine, sixteen files, two parity test binaries and one test-only executable leave the tree, and `lib.rs` loses the public names that existed to feed them. [§AR-system.2.9](../../architecture/README.md#29-api)'s exception — the one component allowed to write to a stream — closes, so [§AR-system.4](../../architecture/README.md#4-dependency-direction)'s three consequences hold without a listed exception and `tests/integration/test_engine_boundary.py` no longer maintains a set of files that may render. One incidental simplification comes with it: `Config::unread_opted_out_blocks`, the counter threaded through the workspace so `check` knows stderr is no longer empty and `success` must not be printed, is what a warning channel answers by construction.

## 4. Consequences

- **The architecture pages move with the implementation, not with this record.** They describe what is built, and this decision builds nothing. The implementation updates [§AR-system.2.9](../../architecture/README.md#29-api) (the api component loses its rendering exception and its `compat/` module), [§AR-bindings.2](../../architecture/AR-bindings.md#2-grund-core-the-only-place-logic-lives) (the engine exposes no `main_entry()` and no renderer; the boundary test keeps no set of files that may render), [§AR-bindings.3](../../architecture/AR-bindings.md#3-grund-cli-the-cli-binary) (the CLI owns `integrations`' parsing and printing like every other command's) and the `compat` row of [§AR-core-module-layout.1](../../architecture/AR-core-module-layout.md#1-module-categories) (ten component directories become nine). [§AR-system.2.8](../../architecture/README.md#28-writers)'s closing sentence about "the deprecated command adapters" of the writers goes with them.
- **The functional spec is settled here.** [§FS-check.4.7](../../functional-spec/FS-check.md#47-a-workspace-member-swallows-the-blocks-own-scan), [§FS-check.4.8](../../functional-spec/FS-check.md#48-unlisted-workspace-block) and [§FS-check.4.10](../../functional-spec/FS-check.md#410-include_root--false-leaves-the-blocks-own-files-unread) each say that the warning travels as one of the run's warnings, where it anchors, and that no byte moves; [§FS-workspace.6.1](../../functional-spec/FS-workspace.md#61-nested-workspaces) says the same for the undecidable ancestor claim; [§FS-lsp.1.1](../../functional-spec/FS-lsp.md#11-diagnostics) says the server publishes all four and [§FS-lsp.4](../../functional-spec/FS-lsp.md#4-determinism-and-parity-with-the-cli) holds them in the parity sweep; [§FS-integrations.1](../../functional-spec/FS-integrations.md#1-user-facing-command) says which side owns the command's rendering; [§FS-distribution.3.1](../../functional-spec/FS-distribution.md#31-rust-grund-core-crate) states the removal path and its two releases.
- **One clause is added to a gate that does not yet read it.** [§FS-distribution.4.2](../../functional-spec/FS-distribution.md#42-a-release-may-not-contradict-the-releases-the-trees-own-messages-name) gains `is removed in <release>`, specified and unimplemented, beside `wording changes in <release>` which is in the same state. The follow-up adds both to `scripts/check_release_ramps.py`'s `CLAUSES` tuple with a deadline test for the deprecation note.
- **One improvement is deliberately not taken.** [§FS-check.4.8](../../functional-spec/FS-check.md#48-unlisted-workspace-block)'s JSON object could now carry the block's `grund.toml` line in `path` and `line`, which its own spec calls the cost of the CLI-level shape rather than a virtue. It keeps the nulls: this change is about which side renders, and a covered JSON surface ([§REQ-backwards-compatibility.1](../../requirements/REQ-backwards-compatibility.md#1-what-is-covered)) should not move inside a refactor that needs no migration. It is a change of its own, for a release that names it.
- **The four warnings reach a surface that never carried them**, which is a verdict change for nobody and a new line for an editor. No exit code, no `success` decision and no CI grep moves, so the release that lands it owes the changelog an entry and no migration.

## 5. Alternatives considered

| Option | Why rejected |
|---|---|
| **Leave `compat/` as it is.** It compiles, the parity tests hold it honest, and `main_entry()` costs nothing while nobody calls it. | It costs the thing this repository is built to protect: one behavior described once. Every message change is made twice and proved equal by two test binaries; [§AR-system.2.9](../../architecture/README.md#29-api) has to carry a permanent exception for the one component allowed to write to a stream; and the four live-path printers keep `workspace/` reading a frontend, the single edge [§AR-system.4](../../architecture/README.md#4-dependency-direction) forbids outright. A deprecation with no named release also never ends — nine releases have shown that — so "later" is not a plan but the absence of one. |
| **Move the four printers into `grund-cli` as callbacks** — the engine takes a `&mut dyn FnMut(&str)` (or a closure per warning) and calls it during expansion. | The engine still decides *when* a line is emitted and in what order, which is rendering policy wearing a data type; and every frontend must supply a sink, so the LSP either supplies one that discards (the disagreement `api/scope_cautions.rs` already fixed once) or invents its own mapping from a string to a diagnostic. A string sink also carries no anchor, so the editor is back to parsing the message for a location — [§AR-bindings.2](../../architecture/AR-bindings.md#2-grund-core-the-only-place-logic-lives)'s prohibition. A returned diagnostic is the same information with the ordering, the anchor and the choice of surface where they belong. |
| **Make the four ordinary located findings** on stdout with the `<path>:<line>:` prefix of [§FS-check.2.1](../../functional-spec/FS-check.md#21-report-format). | Cheapest to implement and the worst for the user: it changes the stream, the shape and the bytes of four messages that repositories grep, for no gain in what they say, and it would put a fact about the run's configuration in the stream reserved for findings about the citation graph. It also breaks the five commands that have no findings stream. [§FS-check.4.8](../../functional-spec/FS-check.md#48-unlisted-workspace-block) already argued this and paid the CLI-level cost once, "on every surface, rather than by giving `check` a located finding and the other commands a different line for the same fact". |
| **Retire `compat/` and leave the LSP silent** — return the diagnostics, publish nothing. | The whole class of defect these four report is a configuration that silently leaves part of a tree unread. The editor is where a `grund.toml` is open and where that is worth saying, and [§FS-lsp.4](../../functional-spec/FS-lsp.md#4-determinism-and-parity-with-the-cli)'s promise is that the two surfaces agree. Keeping the LSP silent would preserve exactly the drift `api/scope_cautions.rs` was created to end. |
| **Remove `main_entry()` in the next minor release** without a naming release, since the symbol has been deprecated for nine of them. | [§REQ-backwards-compatibility.2](../../requirements/REQ-backwards-compatibility.md#2-the-deprecation-path) counts releases that *named* the removal, and none has. The rule is about silence rather than about stasis, and a `grund-core = "0.4"` consumer that upgrades has had no line telling it when its binary stops building. One release of notice costs one release. |
| **Adopt the chosen shape** — data-returning warnings, anchored, byte-identical, `integrations` in the CLI, removal at 0.15.0. | See §2 and §3. |
