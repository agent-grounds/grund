# REQ-discoverable-offline: the installed grund answers for every setting and every check code

The installed `grund` answers, with no network and no other checkout, for every key its configuration accepts and every code `check` can report. For a key it gives the values the key accepts and what it does; for a code, what it means, its severity (fixed, or chosen by a setting) and what turns it on (a setting, a flag, a condition of the tree, or nothing, because it is always on). An answer is in the configuration version the project's file is read as; with no config file it gives both supported versions, version 2 first.

An agent meets a finding code or a key it has not seen at the moment it is working, and a page elsewhere describes another release, or a configuration version the project does not use, and an agent cannot tell which. The binary it runs is the one source that is always its own release, and the project's file says which version applies, so the answer comes from there. That keeps an agent grounded in the tool's own vocabulary as it is in the repository ([§GOAL-agent-grounding](../goals.md#goal-agent-grounding-agents-stay-cited-as-they-work)), lets a user learn a setting at the place an error sent them ([§GOAL-friendliness-first](../goals.md#goal-friendliness-first-as-user--and-agent-friendly-as-possible)), and costs one key or one code rather than the whole reference ([§GOAL-token-economy](../goals.md#goal-token-economy-give-an-agent-the-right-amount-of-spec-not-the-whole-file)). The command that answers is [§FS-config-explain](../functional-spec/FS-config-explain.md#fs-config-explain-grund-config-explain-answers-from-the-installed-binary-and-in-the-version-the-projects-config-is-read-as-what-any-key-accepts-and-means-and-what-any-check-code-means-and-what-turns-it-on).

## 1. Guidance names its version

Shipped help, the setup guide and the init scaffold name a version-specific spelling only in version-neutral wording or together with its version, in its local context.

A spelling is a table or a key as a configuration writes it, such as `[schema.leads.words]` or `[[kinds]] fetch`; one both versions accept is version-neutral already. A spelling's version is named in its local context when "version 1", "version 2", "v1" or "v2" stands in its own sentence, list item or table row; in the heading that encloses it, up to the next heading at the same or a higher level, the nearest such heading winning; or in the sentence that introduces the example it sits in. What `grund init` writes is labelled by the `grund_config_version` of the `grund.toml` it writes, because it renders every file for that one. Help and the guide never load a config, so they cannot speak in the project's version: only the answer of [§REQ-discoverable-offline](REQ-discoverable-offline.md#req-discoverable-offline-the-installed-grund-answers-for-every-setting-and-every-check-code) does.

A spelling may also be named as absent, in one form: "With `grund_config_version = N` there is no `<spelling>`". That sentence holds only where the version-N reader does refuse the spelling, so a refusal written in guidance is checked like any other spelling.

## 2. A refusal is not an answer

A reader refuses a table or a key its version does not admit, and names where its settings are written instead ([§FS-config-v2.reader.1](../functional-spec/FS-config-v2.md#reader1-tables-and-keys-are-closed)). That refusal keeps its own contract and its own bytes, and nothing it prints counts toward the answer this requirement asks for: a key or a code has an answer only where the installed `grund` gives one when asked, whatever an error message happened to say about it.

## 3. Checked, not remembered

The requirement holds because two tests enforce it, as [§REQ-shipped-surfaces.3](REQ-shipped-surfaces.md#3-checked-not-remembered) holds its own:

- `crates/grund-cli/tests/explain_coverage.rs` runs the built binary from a directory outside any checkout, over a version-1 project, a version-2 project and a directory with no config, each with a kind that configures a fetcher which writes a marker file. It takes every table and key from the readers' gates and every code from the catalog, asks for each in each version, and fails on an answer without its values and meaning, or its meaning, severity and what turns it on; on a setting an answer names that its version does not admit; on a planned or misspelt code that is not a query failure; and on the marker.
- `tests/integration/test_guidance_versions.py` reads every help page, every file of the setup skill in both of its copies, and what `grund init` writes. It extracts every spelling from Markdown code spans and TOML fences, from bracketed spellings in help outside its usage synopsis, and from init's TOML parsed as TOML, and asks `grund config explain` in each version whether the spelling exists there. An unlabelled spelling must exist in both versions, a labelled one in its own, and a written refusal must be one its version's reader makes. Its controls run on doctored copies: a true refusal passes, and a false refusal, an unlabelled `[scan] include` and a misspelt `[scna] include` each fail.
