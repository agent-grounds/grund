# DF-markdown-homes-refused-in-1-0: an `md` mapped away from Markdown, a named index or rule home not read as Markdown, and a later value home that is absent or does not hold are refused at load from 1.0.0

**Date:** 2026-11-15

## status: Accepted

## 1. Context

[§DF-markdown-homes-warn-before-1-0](DF-markdown-homes-warn-before-1-0.md#df-markdown-homes-warn-before-1-0-an-md-mapped-away-from-markdown-a-named-index-or-rule-home-not-read-as-markdown-and-a-later-value-home-that-is-absent-or-does-not-hold-warn-from-0230-and-are-refused-from-100) took the deprecation path of [§REQ-backwards-compatibility.2](../../requirements/REQ-backwards-compatibility.md#2-the-deprecation-path) for six version-2 configurations: from grund 0.23.0 each loads with a warning at the config line that has to change, and each warning ends `this becomes an error in grund 1.0.0`. They are `config-md-not-markdown`, `config-index-not-markdown`, `config-rule-file-not-markdown`, `config-rule-folder-not-markdown`, `config-value-home-absent` and `config-value-home-invalid` ([§FS-config-v2.checks](../../functional-spec/FS-config-v2.md#checks-checks)). That record's notice ships with the warnings in 0.23.0, and a notice already released is not published again ([§FS-distribution.4.6.4](../../functional-spec/FS-distribution.md#464-compatibility-notices-come-from-the-decisions)), so the release that keeps the warnings' promise needs a notice of its own, and this record carries it. The release guard holds 1.0.0 while any message still promises a change in it ([§FS-distribution.4.2.2](../../functional-spec/FS-distribution.md#422-the-release-guard-reads-the-releases-the-tree-names)), so 1.0.0 does not ship until this lands, and it lands only after 0.23.0 is tagged: merged earlier, the warnings would reach no release, and a project would meet a refusal it was never warned of ([§DF-markdown-homes-warn-before-1-0.3](DF-markdown-homes-warn-before-1-0.md#3-consequences)).

The six warned on `check`, `config validate` and `config show`, and in the editor, which publishes the reader's load warnings beside its other diagnostics ([§FS-lsp.4.1](../../functional-spec/FS-lsp.md#41-how-parity-is-held)). Every other command loaded such a config in silence.

## 2. Decision

### 2.1 Six load refusals, in their warnings' words

In grund 1.0.0 (agent-grounds/grund#1397), version 2 refuses at load each configuration 0.23.0 warned for, at the line the warning named, exit `2` on every command that loads the config, the editor included ([§FS-lsp.2.2.4.1](../../functional-spec/FS-lsp.md#2241-a-config-that-will-not-load-is-a-diagnostic-on-that-config)), and `1` on `config validate` ([§FS-config.4.3](../../functional-spec/FS-config.md#43-invalid-config-behavior)). Each refusal is its warning with the clause that said what is read "until then" taken out and the remedy kept, ending `; this became an error in grund 1.0.0`:

- `md` mapped to a language not of class `document`, at the entry: ``[schema.sources.extensions] maps `md` to `rust`, which does not read Markdown; `.md` is always Markdown; drop the entry, or map `md` to a `document` language`` ([§FS-config-v2.checks.config-md-not-markdown](../../functional-spec/FS-config-v2.md#checksconfig-md-not-markdown-md-is-mapped-away-from-markdown)). "`.md` is always Markdown" stays, because it is why the entry is refused, and only ", and until then a `.md` file is read as `rust`" goes;
- a named `index` not read as Markdown, at the `index` key: ``[schema.kinds.FS] index` must name a Markdown file; `index.md` is not read as Markdown; name a file a `document` language reads, or set `index = false`` ([§FS-config-v2.checks.config-index-not-markdown](../../functional-spec/FS-config-v2.md#checksconfig-index-not-markdown-a-named-index-is-not-read-as-markdown));
- a rule kind's `files` entry a `source` language reads, wherever it sits in the list, at the `files` key: ``[schema.kinds.RULE] files entry `rules/more.rs` is read as `rust`, which does not read Markdown, and every home of a rule kind must be; move the rules into a file a `document` language reads`` ([§FS-config-v2.checks.config-rule-file-not-markdown](../../functional-spec/FS-config-v2.md#checksconfig-rule-file-not-markdown-a-rule-kinds-files-entry-is-read-as-source));
- a rule kind's `folders` entry where no admitted language reads Markdown, at the `folders` key, for an empty folder, one holding only `.gitkeep` and one that does not exist alike: ``[schema.kinds.RULE] folders entry `rules` can hold no file read as Markdown, because no admitted language reads Markdown; admit one in [schema.sources] languages, such as `markdown`` ([§FS-config-v2.checks.config-rule-folder-not-markdown](../../functional-spec/FS-config-v2.md#checksconfig-rule-folder-not-markdown-a-rule-kinds-folder-can-hold-no-markdown));
- a value row's later home that does not exist, at the key that lists it: ``value home for kind `CONST` does not exist: values/absent.md; create the file, or drop the entry`` ([§FS-config-v2.checks.config-value-home-absent](../../functional-spec/FS-config-v2.md#checksconfig-value-home-absent-a-value-rows-later-home-does-not-exist));
- a value row's later home in the wrong shape, outside the root, or not looked up, at the key that lists it: ``value home for kind `CONST` must be an existing file: values/sub; make it an existing file, or drop the entry`` ([§FS-config-v2.checks.config-value-home-invalid](../../functional-spec/FS-config-v2.md#checksconfig-value-home-invalid-a-value-rows-later-home-is-the-wrong-shape-outside-the-root-or-not-looked-up)).

### 2.2 The codes are spent

Each of the six codes is spent and stays, as `config-fetch-names-nothing` is ([§DF-fetch-names-an-executable-lands-in-0-23](DF-fetch-names-an-executable-lands-in-0-23.md#df-fetch-names-an-executable-lands-in-0-23-a-version-2-fetch-key-that-names-no-executable-is-refused-at-load-from-0230)): `--only <code>` and `--ignore <code>` are still accepted and select nothing, `--only` saying `judged nothing — the check is spent from grund 1.0.0 and never fires` ([§FS-check.1.4.1](../../functional-spec/FS-check.md#141-a-selected-check-the-run-leaves-off-says-so)), no selector suppresses the load refusal, and `grund config explain <code>` answers for the code as spent on any tree ([§REQ-discoverable-offline](../../requirements/REQ-discoverable-offline.md#req-discoverable-offline-the-installed-grund-answers-for-every-setting-and-every-check-code), [§REQ-spec-section-names.permanence](../../requirements/REQ-spec-section-names.md#permanence-a-name-is-permanent)). The `--ignore` the warnings' window offered keeps working, and selects nothing.

### 2.3 The two rows 0.22.x already refused carry the suffix too

`index = "x.rs"`, and a rule `files` entry read as source where the row's first entry is not named `.md`, were refused through grund 0.22.x, loaded with their warnings in 0.23.0, and are refused again in 1.0.0. They carry `this became an error in grund 1.0.0` with the rest. [§DF-fetch-names-an-executable-lands-in-0-23.2](DF-fetch-names-an-executable-lands-in-0-23.md#2-decision) leaves the suffix off a row an earlier release already refused, because the suffix would blame a release that changed nothing about it; 1.0.0 does change these two, against 0.23.0, the release before it, so the suffix names the release that moved their verdict, which is what it is for ([§REQ-backwards-compatibility.2](../../requirements/REQ-backwards-compatibility.md#2-the-deprecation-path)).

### 2.4 A later value home keeps its own message

A later value home is refused with the same verdict as a failed first entry, at load, but not with the same words. The first entry's refusal carries a `hint:` line of its own; a later home's is the one line above, ending "or drop the entry", because dropping an entry is a remedy only for one that is not the first. "As an absent first entry already is" in [§FS-config-v2.checks.config-value-home-absent](../../functional-spec/FS-config-v2.md#checksconfig-value-home-absent-a-value-rows-later-home-does-not-exist) means the verdict.

### 2.5 Only a named index is refused

A row that writes no `index` named nothing, so where the default `README.md` is not read as Markdown its folders are judged as under `index = false`, with no warning and no refusal, as in 0.23.0 ([§DF-markdown-homes-warn-before-1-0.2.1](DF-markdown-homes-warn-before-1-0.md#21-six-load-warnings-each-naming-100)).

### 2.6 Which refusal a file with several gets

The six are asked last: a file that holds one of them and an older refusal anywhere, in the file or in a pinned target the run judges, is refused for the older one, and among the six alone the earliest line is refused. [§FS-config-v2.reader.4.order](../../functional-spec/FS-config-v2.md#reader4order-which-refusal-a-file-with-several-is-refused-for) states the order. So a configuration that 0.23.0 refused for an older reason is refused for that reason still, and the rule row `files = ["rules/rules.md", "rules/more.rs", "rules/other.json"]` keeps the rule-kind refusal at `form` that grund 0.22.x gave it.

### 2.7 What stays

`rule-folder-file-not-markdown`, which `check` reports on a file a `source` language reads inside a rule folder, stays a warning ([§DF-markdown-homes-warn-before-1-0.2.2](DF-markdown-homes-warn-before-1-0.md#22-a-file-in-a-rule-folder-read-as-source-stays-a-warning)). `md = "markdown"`, `md = "v1_markdown"`, which `config migrate` writes, and an `md` mapped to any `document` definition stay silent. An entry the reader already refuses as a place keeps that refusal. Version 1 is unchanged ([§FS-config.5.2](../../functional-spec/FS-config.md#52-a-versions-meaning-moves-only-as-backwards-compatibility-allows)).

## 3. Consequences

From 1.0.0 no configuration grund called contradictory in 0.23.0 loads, so no command can read such a project in a way `check` disagrees with ([§REQ-one-answer](../../requirements/REQ-one-answer.md#req-one-answer-every-command-gives-the-same-answer-about-one-tree)). Main can be cut only as 1.0.0 once this merges, because the tree then says a change was made in it ([§FS-distribution.4.2.2](../../functional-spec/FS-distribution.md#422-the-release-guard-reads-the-releases-the-tree-names)); a 0.23.x fix is cut from a branch off the `v0.23.0` tag.

What grund 0.23.0 built on two of the six goes with them. A version-2 `.md` file is read as Markdown or not at all, so `unread-scan-root` no longer offers to drop an `md` entry, and neither its reason nor `fetch`'s refusal of a folder home's `<ID>.md` says that a `.md` file is read as another language ([§FS-scan.checks.unread-scan-root](../../functional-spec/FS-scan.md#checksunread-scan-root-a-configured-file-root-is-not-read)); the empty-scan caution's mapping repair names another suffix, never `md`. A rule folder no admitted language can read as Markdown no longer reaches the unread-folder warning, whose repairs for a rule folder now always find a document reader admitted ([§FS-scan.checks.unread-scan-root](../../functional-spec/FS-scan.md#checksunread-scan-root-a-configured-file-root-is-not-read)).

## 4. Rejected alternatives

- **Rewrite [§DF-markdown-homes-warn-before-1-0](DF-markdown-homes-warn-before-1-0.md#df-markdown-homes-warn-before-1-0-an-md-mapped-away-from-markdown-a-named-index-or-rule-home-not-read-as-markdown-and-a-later-value-home-that-is-absent-or-does-not-hold-warn-from-0230-and-are-refused-from-100) in place.** Its notice ships in 0.23.0 and is not published again, so 1.0.0's notes would say nothing of six verdicts that move.
- **Report the earliest line in the file, the `md` line ahead of an older refusal.** The six are judged of the source model, and an older refusal stops the reader before that model exists; putting them first would mean judging language classes before lowering, and would change what a configuration 0.23.0 refused for an older reason prints.
- **Remove the codes with the warnings.** A selector that named one would become an unknown-code error, so keeping the promise would break the flag the window offered.

## release-note: Release note

- [§DF-markdown-homes-refused-in-1-0](DF-markdown-homes-refused-in-1-0.md#df-markdown-homes-refused-in-1-0-an-md-mapped-away-from-markdown-a-named-index-or-rule-home-not-read-as-markdown-and-a-later-value-home-that-is-absent-or-does-not-hold-are-refused-at-load-from-100), [§FS-config-v2.checks](../../functional-spec/FS-config-v2.md#checks-checks), [§FS-config-v2.reader.4](../../functional-spec/FS-config-v2.md#reader4-order-and-location-are-kept), [§REQ-backwards-compatibility.2](../../requirements/REQ-backwards-compatibility.md#2-the-deprecation-path): **the six version-2 configurations grund 0.23.0 warned about, each warning naming 1.0.0, are now refused when the config loads.** They warned on `check`, `config validate` and `config show`, and in the editor; the refusal is exit `2` on those and on `fmt`, `fetch`, `show`, `refs` and every other command that loads the config, and `config validate` exits `1`. For example ``error: grund.toml:8: [schema.sources.extensions] maps `md` to `rust`, which does not read Markdown; `.md` is always Markdown; drop the entry, or map `md` to a `document` language; this became an error in grund 1.0.0``. `--only <code>` and `--ignore <code>` with any of the six codes are still accepted and select nothing. **Who this affects:** a version-2 `grund.toml` that drew any of the six warnings. For `config-md-not-markdown`, drop the `md` entry of `[schema.sources.extensions]` or map it to a `document` language such as `markdown`. For `config-index-not-markdown`, name an `index` a `document` language reads, or set `index = false`. For `config-rule-file-not-markdown`, move the rules into a file a `document` language reads. For `config-rule-folder-not-markdown`, admit a language that reads Markdown, such as `markdown`, in `[schema.sources] languages`. For `config-value-home-absent`, create the home or drop the entry. For `config-value-home-invalid`, make the home the shape its key names, inside the project root and accessible, or drop the entry. A file a `source` language reads in a rule folder still draws the `rule-folder-file-not-markdown` warning, and version 1 configs load exactly as before. `unread-scan-root` no longer offers ``Drop the `md` entry from [schema.sources.extensions]``, which only a configuration now refused could reach. Closes [issue #1397](https://github.com/agent-grounds/grund/issues/1397).
