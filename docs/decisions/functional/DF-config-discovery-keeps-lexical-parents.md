# DF-config-discovery-keeps-lexical-parents: config discovery climbs the path's lexical parents before resolving directory links

**Date:** 2026-11-10

## status: Accepted

## 1. Conflict with the existing contract

Discovery canonicalized its start before searching upward. A path through a directory link out of a project therefore searched the target's ancestors, losing the project's config or replacing it with a config above the target. In the reported tree, `grund check` exits `2`, while checks naming the linked directory, a descendant directory, or the invalid-UTF-8 `expected.exit` beneath it exit `0`. Version 2 refuses the outward kind home; version 1 reads it and reports the invalid manifest. This shipped in 0.22.0, as recorded in [issue #1326](https://github.com/agent-grounds/grund/issues/1326).

The version-1 green verdict violates the pre-existing hard prohibition [§REQ-no-missed-citation.1](../../requirements/REQ-no-missed-citation.md#1-no-silent-skips): a file the scan cannot read is reported at its path and the run exits `2`, never passing as if complete. Narrowing to that very file cannot exempt it: [§FS-check.1.3.6.3](../../functional-spec/FS-check.md#1363-a-file-the-wider-walk-could-not-read-is-said-out-loud) already keeps failures at or under the path fatal. The version-2 green verdict comes from the same config-selection error, bypassing the validation the whole run applies. This correction adds no new refusal policy.

## 2. Decision and compatibility proof

Search upward through lexical ancestors as [§FS-config.1.5](../../functional-spec/FS-config.md#15-the-ancestor-search-keeps-the-path-through-directory-links) defines, for the ordinary discovery, explain, and migration lookups alike, and for the workspace `grund init` teaches, an editor folder, and the member a scope lies in. Preserve canonical identity, read and report rules after selecting the config. The narrowed forms then load the same governing config as the whole-run controls: version 2 exits `2` on the outward home; version 1 exits `2` on the invalid manifest and prints its version warning. A target-side config cannot take over merely because the path crosses the link.

The correction route of [§REQ-backwards-compatibility.5](../../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids) applies: the old verdict violated [§REQ-no-missed-citation.1](../../requirements/REQ-no-missed-citation.md#1-no-silent-skips), and that prohibition already applied when the old verdict shipped in 0.22.0. The deprecation path ([§REQ-backwards-compatibility.2](../../requirements/REQ-backwards-compatibility.md#2-the-deprecation-path)) cannot fit: carrying the old green verdict beside the correct one would keep certifying an incomplete run, and there is no old authoring form to retire. The mechanical migration route ([§REQ-backwards-compatibility.3](../../requirements/REQ-backwards-compatibility.md#3-loud-mechanical-migrations)) has no single command that completes the change: the config and path already have defined meanings, and repairing a manifest's bytes or relocating a kind home requires the maintainer's choice. This route cannot justify ordinary policy tightening, feature removal, or a newly invented prohibition.

The correcting release is **0.22.2**: the repository is on `0.22.2-dev` after tag `v0.22.1`. Findings retain their established locations and remedies. Version 1 names the manifest and asks the maintainer to make the path readable or keep it out of the scan. Version 2 names the config line and outward home; move the home inside the project root and update that folder entry. Existing wording does not change. Hooks and editors that narrow to changed paths may now receive exit `2` where they previously received `0`; whole-project checks already gave that answer.

## release-note: Release note

- [§DF-config-discovery-keeps-lexical-parents](DF-config-discovery-keeps-lexical-parents.md#df-config-discovery-keeps-lexical-parents-config-discovery-climbs-the-paths-lexical-parents-before-resolving-directory-links), [§REQ-no-missed-citation.1](../../requirements/REQ-no-missed-citation.md#1-no-silent-skips), [§REQ-backwards-compatibility.5](../../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids): In **0.22.2**, the verdict changes from exit `0` to `2` for a narrowed `check` whose governing config refuses an outward kind home or whose scope holds an unreadable manifest. Commands through directory links, including `config explain` and `config migrate`, search the path's lexical ancestors, so a config above the target or the defaults no longer replace the enclosing project's config. The same search now finds the workspace `grund init` teaches, so a linked target no longer lists a stranger workspace's members; the config of a `grund-lsp` workspace folder opened through a link, which now reports that project's config errors; and the member a narrowed run lies in, so a path under a member with no config of its own runs as that member, its paths spelled from the member, even where it links out of the workspace or into another member. Every finding names its location and the action to take: repair the unreadable manifest named by the version-1 finding, or move the outward version-2 kind home inside the project and update its config entry. No link traversal policy changes.
