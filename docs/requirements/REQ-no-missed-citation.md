# REQ-no-missed-citation: every citation the run reads is checked

A citation the scanner does not see cannot dangle, so a missed site turns `success` into a lie. Every `§`-marked citation in the text a run reads is recognised and validated — Markdown prose and each supported doc-comment form alike ([§GOAL-polyglot-citation](../goals.md#goal-polyglot-citation-ids-cite-cleanly-from-anywhere-they-are-useful)) — and false negatives are bugs ([§GOAL-no-dangling-refs](../goals.md#goal-no-dangling-refs-every-cited-id-resolves-to-a-declaration)).

## 1. No silent skips

A file the scan cannot read is reported at its path and the run exits `2` — the report may be true as far as it got, but it is not complete, and it never passes as if it were ([§FS-check.2](../functional-spec/FS-check.md#2-outputs)). A walk that matches nothing is reported too, as a warning naming what was searched: an empty tree is not a failure, but it must never look like a clean one.

## 2. Every blind spot is declared and bounded

Regions the scanner deliberately does not read are legitimate; regions nobody wrote down are not. Each one must be stated in the spec, chosen by the repository or by a rule the repository can see, and answerable on demand.

- **Out of scope.** `[scan] include` and every walked kind home are the roots the walk starts from, so a citation in a file neither of them reaches is invisible rather than checked — it neither resolves nor dangles ([§FS-config.3.5](../functional-spec/FS-config.md#35-scan--what-gets-scanned), [§FS-check.1.3](../functional-spec/FS-check.md#13-the-full-tree-scope---full)). `grund check --full` widens the walk to the whole config root and reports what points at nothing out there ([§FS-check.3.14](../functional-spec/FS-check.md#314-out-of-scope-unresolvable-citation---full-only)). A blind spot nobody can look into would be a false negative; this one has a light switch.
- **Reported on only where you pointed.** A run given an explicit path reads the whole enclosing project and reports findings only for the files at or under the path ([§FS-scan.path.check](../functional-spec/FS-scan.md#pathcheck-check-reads-more-than-it-reports)). This one is a *reporting* boundary and not a reading one: nothing goes unresolved for lying outside the path, so no citation is missed and no edge is uncounted — the run simply declines to answer about files nobody asked about. The light switch is the argument itself: drop it, or widen it, and the same run says what it found everywhere.
- **Not text the scanner treats as prose.** Fenced code blocks are skipped, which is what makes an illustration in documentation safe to write ([§FS-check.1.1](../functional-spec/FS-check.md#11-recognized-citations)). Inline code and string literals stay live for unqualified citations; in source files only, they are skipped for the namespace-qualified form, because `alias/ID` is shaped like a path, and neither skip applies in Markdown ([§FS-check.1.1](../functional-spec/FS-check.md#11-recognized-citations)). The qualified skip reaches the interior lines of a string literal that spans lines only for the forms [§FS-languages.multi-line-string.forms](../functional-spec/FS-languages.md#multi-line-stringforms-the-recognized-forms) lists, and only within [§FS-languages.multi-line-string.bound](../functional-spec/FS-languages.md#multi-line-stringbound-what-keeps-a-misread-opener-from-swallowing-a-file): an opener counts only in code and only once its closer is found, so no apostrophe and no unclosed opener can start a span. The forms it leaves out are declared in [§FS-languages.multi-line-string.unrecognized](../functional-spec/FS-languages.md#multi-line-stringunrecognized-the-forms-that-are-not-carried), and each recognized form is proved by an executable case ([§REQ-no-missed-citation.3](REQ-no-missed-citation.md#3-proven-per-host-language)).
- **Not walked at all.** Hidden directories, `[scan] exclude` names, ignore-file matches, and E2E fixture trees are pruned wherever a walk descends into them, `--full` included — they prune a descendant and never a root the walk was told to start from. A hidden file name and a non-scanned extension are rules about a file's own name, so they also reach a root: a hidden-named root is the declared blind spot of [§FS-scan.scope.hidden](../functional-spec/FS-scan.md#scopehidden-a-hidden-file-is-not-read-and-the-rule-is-not-about-descent), and a file root refused for its name or its extension is named in the run's report ([§FS-scan.scope.extensions.root](../functional-spec/FS-scan.md#scopeextensionsroot-a-file-root-whose-extension-is-unlisted-is-not-read-and-check-says-so)). See also ([§FS-check.1.3](../functional-spec/FS-check.md#13-the-full-tree-scope---full)).
- **A workspace namespace the repository declared may be absent.** A member listed in `[workspace] optional_members` and missing from this checkout is not read, so a citation into it neither resolves nor dangles ([§FS-workspace.2.2](../functional-spec/FS-workspace.md#22-a-member-that-may-be-legitimately-absent)). The repository chooses it one written entry at a time, and every run that skips one names the namespace in its report and withholds `success` ([§FS-check.4.9](../functional-spec/FS-check.md#49-a-workspace-member-declared-optional-is-absent)). The light switch here is the checkout: fetch the member and the same run checks it.
- **Not read for citations: a YAML value source's comments.** A value source is catalog input that contributes no citations, and a YAML one may carry comments, so a `§` citation written in one is read by no pass and neither resolves nor dangles ([§FS-values.2.2](../functional-spec/FS-values.md#22-declarations-from-value-sources)). The repository chooses it by keeping YAML in a value home, and the guide says to cite a value's provenance from Markdown instead, until a later change reads those comments.

The obligation this creates is on the spec, not the scanner: a skip that no section names is the bug, because it is the one a reader cannot plan around.

## 3. Proven per host language

Every doc-comment form the scanner claims to support is exercised by an executable case in which a **dangling** citation planted in that form fails the check. The dangling direction is what proves the citation was *found* — a passing fixture cannot, since a missed citation also yields `success`. A form the default configuration cannot reach is not supported: advertising a comment prefix whose file extension `[scan] extensions` omits is a claim with no path to being true. `tests/integration/host_language_dangling_proof.rs` reads every golden's `unknown reference` lines back to the fixture and fails the first default extension or comment prefix without a dangling case.
