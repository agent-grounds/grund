- [§FS-examples.5.3](../../functional-spec/FS-examples.md#53-commandargs-is-read-as-shell-words-or-refused): the runner every e2e case and example goes through now reads `command.args` as shell words. A single-quoted argument, as in `id FS 'Password reset' {repo} --explain`, is one argument with its quotes removed, as a double-quoted one already was; quoted and unquoted parts with nothing between them join, and either quote is an ordinary character inside the other. A backslash outside single quotes and an unclosed quote are refused before `grund` runs, by a message that names the case, `command.args` and the line. They used to reach `grund` as several arguments with the quote characters attached, or, for an unclosed double quote, panic naming neither the case nor the manifest, so a case author read `grund`'s complaint about its argument count against a case written the way a shell takes it. Nothing `grund` itself does changes: this is the repository's own harness, and `grund E2E-<name> --format=json` still splits `args` as before. Closes [issue #295](https://github.com/agent-grounds/grund/issues/295). (PR #TBD)
