- [§FS-values.3.1.2](../../functional-spec/FS-values.md#312-a-binding-aimed-at-the-root), [§FS-values.5.2.2](../../functional-spec/FS-values.md#522-a-root-aimed-mismatch-names-the-first-unequal-component), [§DA-root-aimed-value-bindings](../../decisions/architectural/DA-root-aimed-value-bindings.md#da-root-aimed-value-bindings-a-value-binding-may-aim-at-the-whole-root-its-components-joined-by-one-ascii-space): a value binding may aim at a whole value or a value root, so an amount and its unit are one checked literal — `` `1200.0 USD` `` against `CONST-field-price` — instead of a bound amount beside a unit left in prose. The component coordinate becomes optional in the one binding grammar; the literal is the root's components joined by one ASCII space, split at U+0020 alone and compared part by part, each under its own component's equality rule. A disagreement names the first unequal component in the existing mismatch text, or, when the part count differs, the root and its joined components at component 1's site; a value with an ASCII space inside a component is refused at its root and stays bindable by coordinate. Go-to-definition from a root-aimed binding lands on the root ([§FS-lsp.1.3.5](../../functional-spec/FS-lsp.md#135-values-and-named-sections)). A delimited citation of a declaration that is not a value stays ordinary prose. (PR #382)
