- [§FS-declarations.line.section-suffix](../../functional-spec/FS-declarations.md#linesection-suffix-an-id-with-a-section-after-it-declares-nothing): a line that opens with an ID followed by a section, such as `FS-042-user-login.2 is named here` in a Python docstring, `// FS-042-user-login.2 / …` in a function body or `# FS-042-user-login.2 and …` in a Markdown file, now declares nothing. Each of these used to declare the parent ID with the title `.2 …`. That collided with the real declaration as a `duplicate declaration` and an `ambiguous ID` naming a file that only wrote *about* the point, and where nothing collided it made an ID that no specification declares resolve. The separator that counts is the configured `[id] section_separator`, and a named section counts where `named_sections` is on. The line raises no near miss, and with the declaration colon (`# FS-042-user-login.2: …`) it stays the near miss it already was, never a declaration of the parent. A line that opens with a bare ID declares as before. Closes [issue #303](https://github.com/agent-grounds/grund/issues/303). (PR #TBD)
