### Compatibility notices

- [§DF-cli-non-utf8-arguments](../decisions/functional/DF-cli-non-utf8-arguments.md#df-cli-non-utf8-arguments-refuse-non-utf-8-argv-before-dispatch-while-preserving-version-precedence), [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids): process verdicts change from panic exit `101` to an explicit exit `2` refusal for non-UTF-8 arguments, or to exit `0` with the normal version line when literal `--version` or `-V` occurs anywhere. Scripts passing filesystem names may notice the status change. The old verdict violated [§REQ-never-crashes.1](../requirements/REQ-never-crashes.md#1-every-failure-is-a-diagnostic) and [§REQ-never-crashes.2](../requirements/REQ-never-crashes.md#2-exit-codes-are-the-api); every finding replacing it identifies its location as the escaped argument and the action is to pass UTF-8, renaming the path or naming a UTF-8 parent directory. Refusal occurs before any write; valid UTF-8 invocations keep their behavior. Closes [issue #1259](https://github.com/agent-grounds/grund/issues/1259).
- `grund config migrate --to 2` on a version-1 block with `include_root = false`, whose own default scope is empty, now writes only the version line and its `[workspace]` table and reports the dropped defaults as `dropped:` notices. It no longer refuses on `[id] named_sections` or a missing default `[scan] include`, and the report gate still holds the write.
- [§FS-declarations.e2e-case.failure](../functional-spec/FS-declarations.md#e2e-casefailure-a-case-that-cannot-be-read-fails-alone), [§DF-e2e-case-failure-at-the-file](../decisions/functional/DF-e2e-case-failure-at-the-file.md#df-e2e-case-failure-at-the-file-a-failure-reading-an-e2e-case-is-located-at-the-file-that-failed-and-path-scoped-exits-move-with-it-in-both-directions), [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), [§REQ-no-missed-citation.1](../requirements/REQ-no-missed-citation.md#1-no-silent-skips): **a failure reading an E2E case is located at the file that failed, so path-scoped exits move in both directions.** A `command.args`, `expected.exit` or `spec.refs` that cannot be read or decoded, an `expected.exit` that does not parse, and a fixture directory that cannot be listed are reported at that path, under the kind's configured folder, rather than at a fixed `e2e/cases`, and every one a case holds is reported. **Exits move to `2`:** `grund check <path>` exits `2` where the path holds the failing file, whether it names the file, its case, the cases root or a directory above it, where it passed at `0` or stopped at `1`. Make the file readable, or repair its contents. **Exits move down from `2`:** with the kind's folder elsewhere, `grund check e2e` or `grund check e2e/cases` over a directory that happens to have that name now answers about that directory, `0` or `1`, and cautions about the file that failed. **Who notices:** a hook or CI step narrowed to paths in a tree holding a bad case, and a script matching the line or `check --format json`'s `path` on `e2e/cases`, which now holds the file. A run naming a healthy case keeps its caution and its exit, and the second line of a fixture directory, or of a manifest the scan's extensions reach, which called the walk's own failure outside, goes where the file has one spelling; past a link, each spelling keeps its own line. The verdict moves by the correction route of [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), because a file the scan cannot read is reported at its path under [§REQ-no-missed-citation.1](../requirements/REQ-no-missed-citation.md#1-no-silent-skips), and every finding that replaces the old verdict names its location and the action to take. Closes [issue #1264](https://github.com/agent-grounds/grund/issues/1264).
- [§FS-declarations.e2e-case.excluded](../functional-spec/FS-declarations.md#e2e-caseexcluded-exclude-and-an-ignore-file-keep-a-case-out), [§FS-check.2.4.2](../functional-spec/FS-check.md#242-one-failure-one-line), [§DF-e2e-case-on-the-one-walk](../decisions/functional/DF-e2e-case-on-the-one-walk.md#df-e2e-case-on-the-one-walk-an-e2e-case-is-read-by-the-one-walk-so-exclude-and-ignore-files-keep-it-out-and-a-scan-failure-is-one-line-at-the-path-that-failed), [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), [§REQ-no-wrong-citation.1](../requirements/REQ-no-wrong-citation.md#1-no-wrong-resolution), [§REQ-no-wrong-citation.2](../requirements/REQ-no-wrong-citation.md#2-no-false-alarms): **an E2E case that `exclude` or an ignore file matches is no longer read, and a scan failure is one line at the path that failed.** **Exits move down from `2`:** a run over a tree whose only scan failure is in an excluded case exits on the rest of the tree. **Exits move up from `0`:** a citation of an excluded case dangles, and `grund list` no longer names it; drop the citation, or take the case out of `exclude` or the ignore file. **What does not move:** what a case holds is read whole, so a pattern or an ignore file that matches a path inside a case directory keeps out neither that path nor the case, and the fixture list `grund E2E-<name>` prints is what it was. **Bytes only:** an ignore file with several malformed lines is reported at the ignore file, relative, each bad line once, where it was reported at every walk root with its absolute path; and one unreadable manifest reached under two spellings is one line and one `io` entry. **Who notices:** a repository that excludes a case directory it still cites, and a script matching the walk root in an ignore file's error line. The verdict moves by the correction route of [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), because the old verdicts were false alarms or wrong resolutions under [§REQ-no-wrong-citation.2](../requirements/REQ-no-wrong-citation.md#2-no-false-alarms) and [§REQ-no-wrong-citation.1](../requirements/REQ-no-wrong-citation.md#1-no-wrong-resolution), and every finding that replaces an old verdict names its location and the action to take. Closes [issue #1271](https://github.com/agent-grounds/grund/issues/1271).
- [§FS-declarations.e2e-case.failure](../functional-spec/FS-declarations.md#e2e-casefailure-a-case-that-cannot-be-read-fails-alone), [§DF-e2e-case-read-failure-fails-alone](../decisions/functional/DF-e2e-case-read-failure-fails-alone.md#df-e2e-case-read-failure-fails-alone-a-failure-reading-one-e2e-case-is-that-cases-alone-and-path-scoped-exits-move-with-it-in-both-directions), [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids): **a failure reading one E2E case is that case's alone, so path-scoped exits move in both directions.** A `command.args`, `expected.exit` or `spec.refs` that cannot be read or decoded, an `expected.exit` that does not parse, or fixtures that cannot be listed no longer end the walk over the cases: every other case is read wherever it sorts, and each failing case is reported. A run narrowed to a path now gets the answers a tree with no bad case gives about those cases' IDs. **Exits move from `0` to `1`:** `grund check <path>` fails where its path holds a case sorted after a bad one, but not the file that failed, and that case has a finding of its own; where it names a file declaring the same ID as such a case, on `duplicate declaration`; and, under `shorthand = "accepted"`, where such a case makes a number-only citation ambiguous. Each passed without reading the case: do what the finding says. **Exits move from `1` to `0`:** `grund check <path>` whose only errors said such a case's ID does not resolve now passes, whether they read `unknown reference`, `shorthand citation … matches no declaration` or, for a rule naming the case, `literal subject … does not resolve`, along with the `ungrounded source file` that follows from those citations. Those citations and rules were correct: leave them alone, and repair the bad case to clear the warning that still stands in place of `success`. **Who notices:** a hook or CI step narrowed to paths in a tree holding a bad case, and a script reading a whole-project report, which still exits `2` but now carries later cases' findings and IDs, and one `error:` line, and under `check --format json` one `io` entry, per failing case. The verdict moves by the correction route of [§REQ-backwards-compatibility.5](../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), because the old exit `1` broke [§REQ-no-wrong-citation.2](../requirements/REQ-no-wrong-citation.md#2-no-false-alarms) and the old exit `0` broke [§REQ-no-missed-citation.1](../requirements/REQ-no-missed-citation.md#1-no-silent-skips) or, for a duplicate or an ambiguous shorthand, [§REQ-no-wrong-citation.1](../requirements/REQ-no-wrong-citation.md#1-no-wrong-resolution); every finding that replaces it names its location and the action to take. Closes [issue #1256](https://github.com/agent-grounds/grund/issues/1256).
