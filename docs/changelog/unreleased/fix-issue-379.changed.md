- [§FS-distribution.4.12](../../functional-spec/FS-distribution.md#412-pending-changelog-entries-are-one-file-each), [§FS-distribution.4.6](../../functional-spec/FS-distribution.md#46-the-changelog-gate-keeps-the-release-section-mappable-to-its-pull-requests), [§FS-distribution.4.5](../../functional-spec/FS-distribution.md#45-what-the-version-bump-includes): **a pending change is one file of its own under `docs/changelog/unreleased/`**, named `<slug>.<category>.md` and holding the one bullet the release publishes, so two pull requests that each record a change no longer conflict in `docs/changelog.md`, whose `## Unreleased` now holds only a pointer to the directory. The changelog gate asks for an entry whose slug the merge base does not hold and, when there is none, names the file to add; `prepare` groups the entries by category, oldest-landed first, rebases their links and deletes them; `preview` prints that section without writing it; and `stamp` numbers each entry by the pull request whose commit added it. Who this breaks: an open pull request that edits `## Unreleased` conflicts once more and must move its bullet into an entry file; editing an existing entry no longer satisfies the gate on its own, a deliberate narrowing of what counted before; and `stamp` writes a number only at an entry's end, never over a `PR #TBD` its prose quotes.
