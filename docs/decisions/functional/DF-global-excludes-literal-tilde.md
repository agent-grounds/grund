# DF-global-excludes-literal-tilde: preserve literal tildes in the global excludes pathname

**Date:** 2026-10-17

## status: Accepted

## 1. Context

[§FS-scan.scope.ignore-files](../../functional-spec/FS-scan.md#scopeignore-files-respect_gitignore--the-ignore-files) already promises to honor Git's global `core.excludesFile`. The `ignore` dependency instead replaces every `~` in its configured pathname with the home directory. An absolute `/work/a~b/global.ignore` therefore names a different file inside the loader. Usually that file does not exist, and no global patterns load. Git reads the intended file. This affects Linux as well as Windows, where temporary paths often contain short names such as `RUNNER~1`. It is distinct from the repository anchoring repaired by [§DF-global-excludes-anchor-at-the-repository-top](DF-global-excludes-anchor-at-the-repository-top.md#df-global-excludes-anchor-at-the-repository-top-a-global-excludes-pattern-anchors-at-the-repository-top-wherever-grund-runs-from): here the intended file never loads, whatever its patterns or the working directory.

## 2. Decision

[§FS-scan.scope.ignore-files.pathname](../../functional-spec/FS-scan.md#scopeignore-filespathname-the-global-excludes-filename-is-the-one-git-resolves) defines the correction: load the existing readable file Git resolves, preserving literal tildes and expanding a leading home abbreviation once. The scan, probe and stub predicate must agree on that file. Retain configuration discovery, precedence, repository anchoring and the `respect_gitignore = false` opt-out. Do not canonicalize away the regression fixture's literal tilde. A general warning or exit policy for missing or unreadable excludes files is deferred; it needs a separate contract distinguishing configured failures from absent optional defaults.

## 3. Proof of the prior prohibition

The correction follows [§REQ-backwards-compatibility.5](../../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids). The prior verdict violated [§REQ-deterministic-output.2](../../requirements/REQ-deterministic-output.md#2-input-is-the-tree-the-config-and-the-invocation). That prohibition already applied when the affected release shipped: tag `v0.18.0` contains the same three-input rule. The tree (including Git's effective ignore state), the discovered grund config and the invocation determine the bytes; an unrelated environment value may not become a hidden input. The pathname promise alone is a functional specification, not the separately declared hard requirement this route needs.

For an absolute `core.excludesFile` containing an interior tilde, changing `HOME` does not change Git's resolved file or ignore decisions. But the old loader substitutes that unrelated value into the absolute pathname. If one substituted pathname happens to exist and another does not, the declaration set changes with `HOME` while the tree, effective Git ignore state, grund config and invocation remain fixed. `an_absolute_global_excludes_path_is_independent_of_home` in `crates/grund-cli/tests/global_excludes_path.rs` constructs precisely that witness on Unix: both homes and both files exist before either run; Git ignores the target for both homes; the old grund outputs differ. This proves a hidden input, rather than inferring determinism merely from two differently named config values. The cross-platform control/interior-tilde test separately pins loading the intended file.

This accepted record supplies the proof. [§REQ-backwards-compatibility.2](../../requirements/REQ-backwards-compatibility.md#2-the-deprecation-path) does not fit: retaining the substitution for a deprecation window retains the hidden input, and there is no deprecated user form beside a replacement. [§REQ-backwards-compatibility.3](../../requirements/REQ-backwards-compatibility.md#3-loud-mechanical-migrations) does not fit: the global file is outside the repository and there is no single mechanical migration that can decide which declarations a repository needs. This correction cannot justify ordinary policy tightening, feature removal or a new prohibition; no new ignore policy is introduced. The correcting release carries the `release-note` below, and every replacement finding remains located and clearable by the remedies in [§DF-global-excludes-literal-tilde.4](DF-global-excludes-literal-tilde.md#4-affected-verdicts-and-remedies).

## 4. Affected verdicts and remedies

For the usual case where the substituted filename was absent, files ignored by the intended global file stop being scanned. A finding inside one disappears. A citation elsewhere that resolved only to a declaration in one becomes a located dangling-citation error; a declaration cited only from one can become uncited or its file ungrounded; a citation rule satisfied only there can fail. Move the needed declaration or citation out of the ignored region, or re-include the path with a higher-precedence `!` rule in the repository's `.gitignore`. The findings name the affected citation, declaration, file or rule.

If a different, substituted file happened to exist, replacing its patterns with the intended file's patterns can also bring files back into the scan. Findings inside those files are now reported at their locations. Correct those findings, or ignore the files deliberately in the repository's `.gitignore`. A stub to an ignored target is refused and names the stub, excludes file and pattern, with the remedy of moving the target or ceasing to ignore it ([§FS-declarations.stubs.target.3](../../functional-spec/FS-declarations.md#stubstarget3-a-target-the-scan-does-not-read-declares-nothing)). That error is part of the unreleased 0.19.0 refusal ([§DF-stub-target-exclusions](DF-stub-target-exclusions.md#df-stub-target-exclusions-excluded-and-ignored-stub-targets-are-broken-from-grund-0190)), rather than a newly shipped severity change here.

## release-note: Release note

- [§FS-scan.scope.ignore-files.pathname](../../functional-spec/FS-scan.md#scopeignore-filespathname-the-global-excludes-filename-is-the-one-git-resolves), [§REQ-deterministic-output.2](../../requirements/REQ-deterministic-output.md#2-input-is-the-tree-the-config-and-the-invocation), [§REQ-backwards-compatibility.5](../../requirements/REQ-backwards-compatibility.md#5-correcting-a-verdict-another-requirement-forbids), [§DF-global-excludes-literal-tilde](DF-global-excludes-literal-tilde.md#df-global-excludes-literal-tilde-preserve-literal-tildes-in-the-global-excludes-pathname): **grund now loads a readable global `core.excludesFile` whose pathname contains a literal tilde**, including Windows short names such as `RUNNER~1`. Previously the loader substituted the home directory for interior tildes and usually loaded nothing. Files Git ignores through the intended file now leave the scan: findings inside them disappear, while citations to their declarations may dangle, declarations only they cited may become uncited or ungrounded, and citation rules they satisfied may fail. If the wrongly substituted file existed, correcting which patterns load can also bring files and their findings back into the scan. The verdict changes where these patterns alter the scan; every finding names its location and the action to fix it: move needed declarations or citations out of ignored paths, re-include needed paths with `!` rules in the repository's `.gitignore`, or deliberately ignore newly read files there. Ignored stub targets receive the existing 0.19.0 refusal naming the stub, excludes file, pattern and remedy. Valid leading `~/` expansion, including a literal tilde in the home pathname, remains supported. This does not introduce general diagnostics for missing or unreadable global files. Closes [issue #788](https://github.com/agent-grounds/grund/issues/788).
